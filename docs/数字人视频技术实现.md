# 数字人视频技术实现方法

> 项目：AuctionPropertyShortVideoAgentSystem
> 硬件基线：Windows 11 / i5-13400F / 32GB RAM / RTX 5060 8GB (WDDM)
> 状态：全链路已跑通并固化为 `skills/avatar-video` skill

---

## 1. 总体架构

数字人视频 = **声音**（TTS/语音克隆）+ **形象**（单张图片）+ **口型驱动**（音频驱动的说话人生成）+ **字幕**（ASR 转写 + 烧录）。

```
┌─────────────┐   ┌──────────────┐   ┌────────────────┐   ┌────────────┐   ┌───────────┐
│ 目标文案     │──▶│ 语音生成      │──▶│ 图片+音频→视频  │──▶│ ASR 字幕    │──▶│ ffmpeg烧录 │
│ (text)      │   │ TTS / 克隆    │   │ InfiniteTalk   │   │ Whisper    │   │ MP4+SRT   │
└─────────────┘   └──────────────┘   └────────────────┘   └────────────┘   └───────────┘
                    skills/voice-*     skills/avatar-video   (pipeline 内)   (pipeline 内)
```

四个阶段互相独立、产物落盘，任一阶段失败可单独重跑：

| 阶段 | 输入 | 输出 | 实现 |
|------|------|------|------|
| 1. 语音 | 文案 + （可选）参考音频 | wav/mp3 | Qwen3-TTS 克隆 / edge-tts |
| 2. 视频 | 人物图 + 语音 | 无字幕 mp4 | ComfyUI + InfiniteTalk |
| 3. 字幕 | 语音 | srt | faster-whisper (medium) |
| 4. 烧录 | mp4 + srt | 最终 mp4 | ffmpeg + libass |

一键入口：

```powershell
.venv\Scripts\python.exe skills\avatar-video\scripts\run_pipeline.py `
    --image assets\trump_image.webp --audio assets\voice_clone\trump_qwen_clone.wav `
    --area 256000 --name trump_qwen_clone
```

## 2. 语音：TTS 与声音克隆

### 2.1 Qwen3-TTS（声音克隆，主方案）

- 模型：`models/tts/Qwen3-TTS-12Hz-0.6B-Base`（约 0.6B，8GB 单卡 bf16 轻松放下）
- 两种模式：
  - **精确克隆**：`ref_audio` + `ref_text`（参考文本需与音频内容对齐），质量最好
  - **x-vector 懒人模式**：只要 `ref_audio`，不要参考文本，质量略降
- 实测：71.6s 英文参考音频（`assets/特朗普演讲_参考音频.mp3`）→ 中文克隆语音 14.4s，GPU 上秒级完成

```python
from qwen_tts import Qwen3TTSModel
model = Qwen3TTSModel.from_pretrained(MODEL_DIR, device_map="cuda:0",
                                       dtype=torch.bfloat16,
                                       attn_implementation="eager")
wavs, sr = model.generate_voice_clone(
    text=target_text, language="Chinese",
    ref_audio=ref_audio, ref_text=ref_text)   # 或 x_vector_only_mode=True
```

**Windows 部署关键点（踩坑）**：`qwen_tts` 依赖 `torchaudio.compliance.kaldi`，
而 torchaudio 的原生扩展 `_torchaudio.pyd` 必须与 torch **同版本同 CUDA 构建**，
否则 `import torchaudio` 报 `OSError: [WinError 127] 找不到指定的程序`（DLL 依赖解析失败）。

```powershell
# torch 2.7.1+cu128 就必须装 torchaudio 2.7.1+cu128，不能装 2.11.0+cpu
.venv\Scripts\pip.exe install torchaudio==2.7.1 --index-url https://download.pytorch.org/whl/cu128
```

### 2.2 edge-tts（零依赖备选方案）

- Microsoft 神经语音，云端免费，无需模型权重，音质好但**不可克隆音色**
- 代表音色：`zh-CN-YunxiNeural`（年轻男声）、`zh-CN-YunjianNeural`（浑厚男声）

```python
import edge_tts, asyncio
asyncio.run(edge_tts.Communicate(text, "zh-CN-YunxiNeural").save(out_mp3))
```

## 3. 视频：InfiniteTalk 口型驱动生成

### 3.1 技术原理

InfiniteTalk 是基于 Wan2.1 视频扩散模型的音频驱动说话人生成方案：
**单张图片 + 一段音频 → 任意时长的说话视频**。输入音频经过音频编码器提取特征，
与图像条件一起注入 DiT（扩散 Transformer）去噪过程，模型逐 clip 采样视频帧，
由音频特征驱动嘴部运动与头部姿态。

### 3.2 部署形态

- 形态：**ComfyUI 自定义节点插件**（`D:\Program\ComfyUI\custom_nodes\InfiniteTalk`）
- 工作流：插件自带 `example_workflows/wanvideo_infinitetalk_single_example.json`
- 核心模型权重（`D:\Program\ComfyUI\models\`）：

| 模型 | 用途 |
|------|------|
| Wan2.1-T2V-1.3B (dit) | 视频扩散主模型 |
| umt5-xxl (text encoder) | T5 文本编码（CPU offload） |
| wav2vec2 / audio encoder | 音频特征提取 |
| InfiniteTalk 单段/多段 LoRA | 说话人驱动适配 |

### 3.3 提交方式（脚本化）

`skills/avatar-video/scripts/generate_video.py` 动态改写工作流 JSON 后提交 REST API：

1. 读取模板 JSON → 覆盖图片/音频 widget（**提交时动态注入，不依赖 JSON 内残留路径**）
2. 覆盖分辨率（须为 16 的倍数）、`--area` 像素预算、采样步数
3. `POST /prompt` 提交 → 轮询 `GET /history/<prompt_id>` 至完成
4. 从 ComfyUI temp 目录取回输出 mp4

服务启动（**两个 flag 缺一不可**）：

```powershell
D:\Program\ComfyUI\.venv\Scripts\python.exe main.py `
    --listen 127.0.0.1 --port 8188 `
    --disable-async-offload --disable-cuda-malloc
# 禁止设置 PYTORCH_CUDA_ALLOC_CONF=expandable_segments（见 6.2 崩溃条目）
```

### 3.4 显存优化（8GB 卡跑 1.3B DiT 的核心）

#### (1) Block Swap（层交换 offload）

40 个 DiT block 中仅 2 个常驻 GPU，其余按需从 CPU 内存换入换出，
用「时间换空间」把显存峰值压到 3GB 以内。由工作流节点参数 `blocks_to_swap` 控制：

| blocks_to_swap | 常驻 GPU 层数 | 速度 | 稳定性 |
|---|---|---|---|
| 15 | 25 | 快 | 8GB 下 OOM |
| 38 | **2** | **~3.5 分钟/10s 段** | **稳定（默认）** |

配套修复（插件源码 `nodes.py` / `nodes_model_loading.py`）：
- 文本编码后及时 `del q, k, v, input_x`，消除激活张量泄漏
- 模型分块加载时 `sd[name] = None` 逐个释放权重，压低加载期 RAM 峰值
- TextEncode T5 节点的 `IS_CHANGED` 返回 `nan`，强制每次重新编码，防缓存污染

#### (2) 分辨率 ↔ 序列长度（最有效的调参杠杆）

序列长度 = `(宽/16) × (高/16) × 21`（帧数固定 21/clip）。**宽高必须是 16 的倍数**。

| 分辨率 | 序列长度 | 8GB 卡表现 |
|---|---|---|
| 832×480 | 32760 | 不可行（OOM/极慢） |
| 640×384 / 416×608 | ~20-21k | **3.5 分钟/段，峰值 4.9GB** |
| 544×320 | ~17k | 更快，画质更低 |

`--area`（像素预算）三档：`180000` 快 / `256000` 默认 / `400000` 清晰。

#### (3) 碎片整理与崩溃规避

- 每 4 个 block 完成一次 `torch.cuda.empty_cache()`（源码 `wanvideo/modules/model.py`，
  条件 `b % 4 == 2`）。每 2 个太慢（20 分钟/段），每 4 个是速度/稳定平衡点
- 图片预处理用 `ImageResizeKJv2` + `pillarbox_blur`（模糊填充而非裁切），
  分辨率按原图比例自动计算（`fit_resolution()`，误差 <1.5%）

#### (4) 系统级配合

- **跑之前清后台**：Edge/迅雷/微信/WorkBuddy 合计约 10GB；模型加载峰值
  RAM 掉到 0.1GB 会直接 OOM，入口需 ≥15GB 可用内存
- RAM 与显存不同：block swap 把压力转移到 RAM，8GB VRAM 由 GPU 保证，
  但 CPU 内存不足同样失败

### 3.5 性能基线（实测）

| 配置 | 耗时 | 显存峰值 |
|------|------|----------|
| 640×384, area=256000, 12 段 ×10s | ~40 分钟 | 4.9GB alloc / 7.5GB reserved |
| 416×608, area=180000, 12 段 ×10s | 41 分 44 秒 | 同上 |

单段 10 秒视频 ≈ 3-4 分钟。**时长几乎线性于音频长度**。

## 4. 字幕：Whisper 转写 + 烧录

### 4.1 ASR（faster-whisper）

模型权重已迁至项目内（不依赖 C 盘 HF 缓存）：

```
models/avatar-video/whisper/{tiny,base,small,medium}/   # config/tokenizer/vocab/model.bin
```

| 模型 | 31.7s 音频 CPU int8 耗时 | 中文质量 | 结论 |
|---|---|---|---|
| base | 2.9s | 一般 | 快速预览 |
| small | 7.0s | 有错字（"资寻/全流成"） | — |
| **medium** | **18.3s** | **正确（"咨询/全流程"）** | **默认** |

转写开销仅占视频生成时间的 <1%，所以默认直接上 medium。

```python
from faster_whisper import WhisperModel
model = WhisperModel("models/avatar-video/whisper/medium", device="cpu", compute_type="int8")
segments, _ = model.transcribe(audio, language="zh", word_timestamps=True)
```

注意：**传目录路径而非模型名**——传名字会走 hub 查 revision，离线/镜像环境会报错。

### 4.2 SRT 生成与烧录

- `whisper_srt.py`：音频 → 时间轴对齐的 srt（支持 `--download` 拉权重到项目目录）
- `burn_subtitle.py`：ffmpeg + libass 烧录，企业风格样式（白字黑边、底部居中）

**Windows 路径大坑**：libass 不读非 ASCII 路径、且 Windows 盘符冒号（`D:`）
与 ffmpeg 滤镜语法冲突。解法：

```
1. srt 复制到临时目录
2. ffmpeg 以该目录为 cwd 启动
3. 滤镜写相对路径：subtitles=filename=sub.srt
```

## 6. 关键踩坑清单

### 6.1 torchaudio DLL WinError 127
现象：`import torchaudio` → `OSError: [WinError 127]`。
根因：**torchaudio 与 torch 版本/CUDA 构建不匹配**（2.11.0+cpu 配 2.7.1+cu128）。
解法：`pip install torchaudio==2.7.1 --index-url .../whl/cu128`（与 torch 严格同版本）。
注意：装 VC++ Redistributable 不能解决 ABI 不匹配问题，只是必要的运行时前置。

### 6.2 WDDM 下 CUDA 运行 30+ 分钟必崩
现象：`Failed to create GPU mapping` / `CUDA driver error: device not ready`。
根因：`expandable_segments` 与 WDDM 显存管理冲突；`cuda_malloc.py` 会向已有
`PYTORCH_CUDA_ALLOC_CONF` **追加** `backend:cudaMallocAsync`。
解法：**不要**设置该环境变量，并且启动必须带
`--disable-async-offload --disable-cuda-malloc`。

### 6.3 GBK 控制台编码
现象：含中文路径/输出的 print 抛 `UnicodeEncodeError: 'gbk' codec`。
解法：子进程设 `PYTHONIOENCODING=utf-8`；父进程避免打印非 ASCII（ASCII replace）；
读文件用 `sys.stdout.reconfigure(encoding='utf-8')`。
文件名含中文时用 Python（而非 PowerShell 字面量）定位/复制文件。

### 6.4 libass 非 ASCII 路径
见 4.2：srt 先拷到临时目录，ffmpeg 以该目录为 cwd，滤镜用相对文件名。

### 6.5 后台工具的假错误
bash 工具执行 `Start-Process`/`Stop-Process` 可能报
`ChildProcess.kill` 错误——多为 shell 层假报，用 `GET /system_stats`
探测服务真实状态确认。
